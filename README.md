## 使用指南

### 三個步驟

1. **規格與數據格式**
   - 從「常用配置」下拉選單挑一個串並聯組合（例如 `5S2P`），或直接手動填入 `S`（串聯數）與 `P`（並聯數）。
   - 勾選要輸入的欄位，**勾選順序即為每行的欄位順序**。
     例：同時勾選「電容量 + 電能量 + 內電阻」時，每行就是 `mAh mWh mΩ`。

2. **批次輸入數據**
   - 從 Excel／試算表直接複製整批電芯資料貼上（支援從 Windows 貼上的 `\r\n` 斷行）。
   - **一行 = 一顆電芯**，空行會自動略過。
   - 提示列的「已解析 N 筆」會即時更新，數量足夠時轉為綠色。

3. **配對成果與統計**
   - 按下「開始運算配對」取得每串的總容量、總能量、並聯內阻與具體電芯清單。

### 內建預設配置

| 區段 | 組合 |
| --- | --- |
| 1S - 3S｜單節 / 小型 | 1S1P、2S1P、3S1P、3S2P |
| 4S - 6S｜工具機 / 動力 | 4S1P、4S2P、5S1P、5S2P、5S3P、6S1P、6S2P、6S3P、6S4P |
| 7S - 12S｜中壓電池組 | 7S1P、7S2P、8S1P、8S2P、9S2P、10S2P、10S3P、11S1P、11S2P、12S1P、12S2P |
| 13S 以上｜高壓電池組 | 13S1P、14S1P、16S1P、20S1P |

> 下拉選單與輸入框是**雙向同步**的：手動輸入 `5S2P` 時下拉會自動選取該項目，輸入不在清單中的組合（如 `5S7P`）則顯示為「自訂」。

## 輸入格式

### 欄位分隔符號

同一行的多個欄位可以使用下列**任一種**符號分隔，也可以混著用：

| 類別 | 符號 |
| --- | --- |
| 空白 | 半形空格、全形空格、Tab |
| 逗號類 | `,` `，` `、` |
| 分號類 | `;` `；` |
| 其他 | `\|` `:` `：` `-` `–` `—` `/` `\` `_` |
| 句點 | `.`（預設視為分隔符號，勾選「小數點保留為小數值」後改為小數點） |

連續多個分隔符號不會產生空白欄位，因此以下寫法結果完全相同：

```text
2500 9250 15
2500,9250,15
2500-9250-15
2500_9250_15
2500/9250/15
2500.9250.15
2500-9250_15/13
```

### 換行規則

**換行永遠代表下一顆電芯**，不會被當成分隔符號。若要在一行內塞入多顆電芯，請改用 `;` 等「不會出現在數值中」的符號作為欄位分隔，並確保欄位數量正確。

### 小數值（內阻）

預設 `.` 是分隔符號，因此 `15.5` 會被拆成 `15` 與 `5`。若資料含內阻小數，請勾選輸入框下方的：

> ☑ 小數點保留為小數值（勾選後 `.` 不再是分隔符號，可輸入 15.5 這類內阻）

### 快速範例

```text
# 勾選：電容量 + 電能量 + 內電阻，設定 2S2P
2500 9250 15
2510 9280 14
2480 9230 16
2490 9240 13

# 也可以完全使用符號分隔
2500,9250,15
2510-9280-14
2480/9230/16
2490|9240|13
```

## 演算法原理

配對目標是讓**每一串的總容量盡量一致**（縮小最大值與最小值的極差），流程分三階段：

### 1. 排序（Sort）

依勾選欄位將電芯由大到小排序。預設以**電容量**為主；未勾選容量時改用**電能量**。

### 2. 蛇形分配（Snake-fill）

把排序後的電芯依序填入各組，第 1 輪由左到右、第 2 輪由右到左，依此類推：

```text
S=4, P=3
  1 →  2 →  3 →  4
              ↓
  8 ←  7 ←  6 ←  5
  ↓
  9 → 10 → 11 → 12
```

好處是相鄰電芯不會直接排進同一串，可在後續交換時保留更多調整空間。

### 3. 局部交換優化（Local Search）

重複以下步驟，直到無法再改善或達到迭代上限（30,000 次）：

1. 找出目前總容量**最大**的組（`maxIdx`）與**最小**的組（`minIdx`）。
2. 枚舉這兩組之間所有「一換一」的組合，計算交換後的容量差。
3. 若存在能讓兩組更接近的組合，就執行交換並更新統計。

因為每一步都只接受**嚴格改善**的交換，結果穩定且可重現；對常見的電池資料，結果通常已達到最佳分割。

## 計算公式

| 項目 | 公式 | 說明 |
| --- | --- | --- |
| 單串總容量 | `Σ mAh` | 每串並聯的電芯容量相加 |
| 電池組總能量 | `Σ mWh`（各串相加） | 未勾選電能量欄位時顯示 `N/A` |
| 並聯等效內阻 | `1 / (1/r₁ + 1/r₂ + …)` | 以倒數和計算，無內阻資料時為 `0` |
| 估算總等效內阻 | `Σ R_parallel`（各串相加） | 未勾選內阻欄位時顯示 `N/A` |
| 可用總容量 | `min(各串總容量)` | 受容量最少的那一串限制 |
| 最大串容量偏差 | `max(各串總容量) − min(各串總容量)` | 越小代表配對越均衡 |

## 專案結構

```text
LithiumBatteryTool/
├── index.html      # 單一檔案：HTML 結構 + CSS 樣式 + 演算法 + UI 邏輯
└── README.md       # 專案說明文件
```

`index.html` 內部的 `<script>` 分為兩層，便於維護與測試：

| 區塊 | 內容 |
| --- | --- |
| **核心計算模組** | 純函式，不操作任何 DOM：`tokenizeLine`、`parseCells`、`calcParallelResistance`、`snakeFill`、`optimizeBalancing`、`summarize`、`runPairing` |
| **UI 層** | DOM 事件綁定、狀態提示與報表渲染 |

## 開發規範

- **縮排**：4 個空白；**字串**：單引號；**敘述句**：結尾加上分號。
- **註解與對外文字**：使用繁體中文（`zh-TW`）。
- **變數宣告**：優先 `const`，需要重賦值時才用 `let`。
- **演算法變更**：務必同步更新核心模組的純函式，並確認分組結果未劣化。
- **不要引入外部依賴**：維持單檔、零建置的特性，才能直接部署在 Cloudflare Pages。
